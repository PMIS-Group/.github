# PMIS Support Paths

Use the appropriate PMIS route for the request. Do not include secrets, credentials, production details, or confidential client information in public issues.

| Need | Route |
| --- | --- |
| Normal engineering work | Tracked GitHub issue or approved task-management system |
| Repository or development question | Repository maintainers or Engineering Lead |
| Application defect | Tracked GitHub issue or approved task-management system |
| Production incident | Approved PMIS incident-response channel or process |
| Security vulnerability | Private email to [office@pmis.com](mailto:office@pmis.com) |
| Access request | Engineering Lead or authorized system owner |
| Client or user support | Approved PMIS client-support process |
| Documentation question | Repository maintainers or Engineering Lead |

Security vulnerabilities must not be submitted as public issues. General user support must follow the approved internal support process.
